# alltoone

Продолжение работы с ИИ без потери нити: сессия упирается в лимит контекста —
`/handoff` собирает состояние, карту проекта и нужные файлы в один файл, а новый
чат поднимает работу через `/resume`. Без зависимостей, один `python`.

Три части:

- **`alltoone` (CLI)** — упаковка проекта в один файл и обратно (`pack`, `unpack`).
  Это же основа пакета для переноса: один файл, который читает агент.
- **Workflow переноса** — `STATE.md` (брифинг до 60 строк), `files.txt` (что нужно
  дальше), `pack.md`; команды `/handoff` и `/resume` в OpenCode, `handoff --check`.
- **Плагин `context-budget`** — строка `[budget]` в каждом запросе из реальных
  токенов провайдера и режимы 70/85/92%, по которым агент готовит перенос.

Упаковка остаётся самостоятельным сценарием: отдать проект другому агенту на
анализ, вложить в письмо, оценить объём перед работой.

OpenCode — основной сценарий (метр контекста, команды, навыки), но ядро — CLI и три
файла переноса — работает в любой среде и с любым ассистентом: см. «Другие среды и
другие ИИ».

```
проект/                      alltoone-context.md
├── src/            ──►      ├── дерево проекта
│   ├── main.py              ├── ### `src/main.py` + код
│   └── utils.py             └── ### `src/utils.py` + код
├── README.md
└── .gitignore
```

## OpenCode как основной сценарий

Обычный чат принимает файлы, но не помнит, где остановился. В OpenCode этот набор
закрывает ровно это:

- **Метр из реальных токенов.** Строка `[budget] 158k/200k used (79%)` приходит в
  каждом запросе; цифры берутся из отчёта провайдера, а не из оценки модели.
- **Порог напоминает сам.** 70% — агент обновляет `STATE.md`, 85% — собирает пакет
  и говорит открыть новый чат, 92% — просит остановиться.
- **Перенос одним файлом.** `/handoff` и `/resume` передают не историю, а брифинг:
  цель, сделано, дальше, решения, нужные файлы и полная карта проекта.
- **Кэш не страдает.** Строка уходит в хвост сообщений: 89–96% промпта читается из
  кэша (при инъекции в системный промпт было 2%).
- **Выход всегда на виду.** Каждый запрос заканчивается на `new chat: /resume` —
  даже в `normal`, задолго до порога.
- **Всё локально.** Состояние, список файлов и журнал — в `.opencode/handoff/`.

Цена: одна служебная строка на запрос и ~30k токенов на `/resume`.

## Другие среды и другие ИИ

OpenCode — основной сценарий, но ядро от него не зависит: `alltoone` — обычный CLI
без зависимостей, а перенос работы — это три файла (`STATE.md`, `files.txt`,
`pack.md`). Ничего из этого не привязано к OpenCode.

| что | в OpenCode | без OpenCode |
| --- | --- | --- |
| упаковка и распаковка | CLI | так же, CLI |
| перенос работы | `/handoff`, `/resume`, указатель на пакет | те же три файла; команды — обычные промпты |
| метр контекста | плагин `context-budget` | нет: чекпоинт выбирает человек |
| навыки | `.opencode/skills/` подхватываются сами | те же Markdown-файлы, подключить как правила |

### Чат без доступа к файлам (ChatGPT, Claude, Gemini в браузере)

Единственный мост — файл:

```bash
python -m alltoone . --clipboard                    # в буфер, вставить в чат
python -m alltoone . -o context.md                  # или вложением
python -m alltoone . -f xml -o context.xml          # Claude хорошо читает XML
python -m alltoone . --max-tokens 60000 -o ctx.md   # не влезает — части
```

Продолжение работы: в начале нового чата вставить `pack.md` — он и есть брифинг
(состояние, карта, нужные файлы). `STATE.md` в таком режиме пишет человек или сам
агент, если попросить его в конце сессии.

### Инструменты, которые читают репозиторий

Cursor, Copilot, Claude Code, Aider, Continue, Zed и подобные видят файлы сами,
поэтому упаковка им не нужна — нужен протокол состояния:

```bash
python -m alltoone handoff --check   # проверить STATE.md и files.txt
python -m alltoone handoff           # собрать pack.md, если он им нужен
```

`AGENTS.md` многие читают как есть; если инструмент ждёт своё имя — скопируй:

```bash
cp AGENTS.md CLAUDE.md                                             # Claude Code
mkdir -p .github && cp AGENTS.md .github/copilot-instructions.md   # Copilot
```

Команды `/handoff` и `/resume` — обычные Markdown-промпты
(`.opencode/commands/*.md`): убери frontmatter и вставь текст как промпт или
сохрани как slash-команду своего инструмента.

### Чего не будет без OpenCode

- **Метра.** Строку `[budget]` даёт плагин по реальным токенам провайдера; в других
  средах её нет, а оценивать окно «на глаз» бесполезно. Замена — свой чекпоинт: раз
  в N задач запускать `handoff --check` и `handoff` вручную.
- **Автоуказателя на пакет.** В новом чате пакет надо открыть самому; в OpenCode это
  делает одна строка в первом запросе (`autoResume`).
- **Автосжатия.** Оно и в OpenCode выключено по умолчанию — новый чат с `/resume`
  ничего не теряет.

Упаковка, распаковка, проверка целостности и схема состояния работают одинаково
везде — это и есть переносимая часть.

## Зачем

- **Продолжить в новом чате без пересказа** — состояние, решения и нужные файлы
  уже лежат в пакете; `/resume` их читает.
- **Отдать проект другому агенту одним файлом** — анализ, ревью, вложение в письмо.
- **Уложиться в лимит токенов** — `--max-tokens` режет по границам файлов.
- **Вернуть файлы обратно** — `unpack` проверяет SHA-256 до записи.

## Установка

Нужен только Python 3.10+ — зависимостей у пакета нет. Проект распространяется
папкой: в PyPI его нет, готового пакета не скачать.

### Шаг 1. Проверить Python

```powershell
python --version
```

Ожидается `Python 3.10` или новее. Если открылся Microsoft Store или написано
`python: command not found`, поставь Python с python.org и при установке отметь
галочку **Add python.exe to PATH**, затем закрой и снова открой терминал. На Linux
и macOS обычно есть `python3` — установщик умеет работать и с ним.

### Шаг 2. Получить папку

Скачай архив и распакуй его (или `git clone`). Папку лучше выбрать простую:
`D:\tools\alltoone` или `~/tools/alltoone` — без пробелов и кириллицы в пути это
избавляет от части сюрпризов. Все команды ниже выполняются **из этой папки**:
`scripts\` лежит внутри неё.

### Шаг 3. Запустить установщик

Windows, PowerShell (в Проводнике: Shift + правый клик → «Открыть окно PowerShell
здесь»):

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

`-ExecutionPolicy Bypass` нужен, потому что Windows по умолчанию не запускает
неподписанные скрипты. Разрешение действует только на этот запуск и ничего не
меняет в системе; если политика уже разрешает скрипты, хватит
`.\scripts\install.ps1`.

Linux / macOS:

```bash
chmod +x ./scripts/install.sh
./scripts/install.sh
```

`chmod` нужен, если архив распаковался без права на запуск; после `git clone` его
можно пропустить.

Что делает установщик: проверяет версию Python, ставит пакет в режиме editable
(`python -m pip install -e .`) и печатает версию. Editable значит, что после
`git pull` новый код подхватывается сам — переустанавливать не нужно. Вручную то
же самое: `python -m pip install -e .`, а если системный Python недоступен для
записи — `python -m pip install --user -e .`.

### Шаг 4. Проверить

```bash
alltoone --version    # alltoone 0.5.6
```

Если команда не находится, пакет всё равно работает — запускай его как модуль:

```bash
python -m alltoone --version
python -m alltoone .            # упаковать текущую папку
```

«Не находится» обычно значит, что каталог скриптов Python не попал в `PATH`;
чинить это не обязательно, `python -m alltoone` равнозначен.

### Шаг 5 (по желанию). Развернуть workflow в своём проекте

Установка ставит только CLI. Плагин, команды `/handoff` и `/resume`, `AGENTS.md` и
`opencode.jsonc` кладутся в конкретный проект отдельной командой; папка проекта
должна уже существовать:

```powershell
.\scripts\install.ps1 -Target D:\work\my-project
```

```bash
./scripts/install.sh --target ~/work/my-project
```

Копируются `.opencode/plugins/context-budget`, `.opencode/commands/{handoff,resume}.md`,
`.opencode/skills/skill-template.md`, `AGENTS.md` и `opencode.jsonc`. Состояние
(`.opencode/handoff/`) не копируется никогда — оно принадлежит конкретному проекту;
заработанные навыки тоже остаются у себя, шаблон лишь показывает форму.

Существующие файлы не перезаписываются: строка `skip ... (exists)` в выводе значит,
что файл уже был и остался вашим. Заменить осознанно — `-Force` / `--force`.

Если в проекте уже есть свой `opencode.jsonc`, он останется нетронутым, и метр
контекста не включится: перенеси в него запись `plugins` с `autoResume` из
поставляемого файла (см. «OpenCode как основной сценарий»). Дальше открой проект в
OpenCode и работай как обычно: на 85% контекста — `/handoff`, потом новый чат и
`/resume`.

### Вручную, без скриптов (Проводник)

Скрипты — удобство, а не требование: тот же набор файлов переносится руками, и это
работает в любом проекте, где есть папка. Нужны два окна Проводника (Finder,
Nautilus — без разницы) и перетаскивание.

1. Открой папку alltoone и папку проекта рядом, в двух окнах.
2. В проекте создай папки `.opencode\commands`, `.opencode\plugins`,
   `.opencode\skills` — с точкой впереди и без ошибок в именах.
3. Скопируй файлы:

| Откуда (в alltoone) | Куда (в проекте) |
| --- | --- |
| `.opencode\plugins\context-budget\` — папку целиком | `.opencode\plugins\context-budget\` |
| `.opencode\commands\handoff.md` | `.opencode\commands\handoff.md` |
| `.opencode\commands\resume.md` | `.opencode\commands\resume.md` |
| `.opencode\skills\skill-template.md` | `.opencode\skills\skill-template.md` |
| `AGENTS.md` | `AGENTS.md`, корень проекта |
| `opencode.jsonc` | `opencode.jsonc`, корень проекта |

Не копируй `.opencode\handoff\` (это состояние конкретной работы), `pack.md` и
папки навыков вроде `powershell-native-stderr`: они заработаны здесь и к чужому
проекту отношения не имеют.

Если какой-то из этих файлов в проекте уже есть и вы его правили, оставьте свой:
копируйте только недостающие — это то же, что `skip ... (exists)` у установщика.

4. Если в проекте уже есть свой `opencode.jsonc`, не заменяй его — открой оба файла
   Блокнотом и перенеси в свой только блок `plugins`, иначе метр не включится:

   ```jsonc
   "plugins": [
     {
       "package": "./.opencode/plugins/context-budget",
       "options": { "autoCompact": false, "autoResume": true },
     },
   ]
   ```

   Блок вставляется внутрь фигурных скобок верхнего уровня; запятая после него
   нужна, если ниже есть другие ключи. Если своего файла нет — просто скопируй
   поставляемый целиком.

5. Проверка: открой проект в OpenCode. В списке команд должны появиться `/handoff`
   и `/resume`, а в первом же запросе — строка `[budget]`.

Копирование ставит только workflow, но не CLI: `/handoff` запускает
`python -m alltoone handoff`, поэтому пакет должен быть установлен (шаг 3).
Проверить это можно из папки проекта: `python -m alltoone --version`.

В macOS Finder скрывает имена с точкой: включи показ через `Cmd + Shift + .`,
иначе `.opencode` просто не видно. В Windows Проводнике такие папки видны обычным
образом; если не видно расширений файлов, включи «Расширения имён файлов» в
«Параметры папок».

### Параметры установщика

| Параметр | Смысл |
| --- | --- |
| `-Target DIR` / `--target DIR` | куда положить workflow (шаг 5) |
| `-Force` / `--force` | перезаписать существующие файлы |
| `-Python PATH` / `--python PATH` | каким Python ставить |
| `-h` / `--help` | краткая справка (только `.sh`) |

### Если что-то пошло не так

| Что видно в консоли | Что делать |
| --- | --- |
| `python not found` | Python не установлен или не попал в `PATH` — шаг 1 |
| `python 3.8 is too old` | Поставить 3.10+ и указать его: `-Python путь` / `--python путь` |
| `pip install failed` | Системный Python недоступен для записи: `python -m venv .venv`, затем запустить установщик с `-Python .venv\Scripts\python.exe` (на Linux/macOS — `--python .venv/bin/python`) |
| `running scripts is disabled` | Запустить через `powershell -ExecutionPolicy Bypass -File ...` |
| `Permission denied` (Linux/macOS) | `chmod +x ./scripts/install.sh` |
| `target is the repository itself` | `-Target` указывает на саму папку alltoone; нужен другой проект |
| `not a directory` | Папки проекта ещё нет — создать и повторить |

Повторный запуск установщика безопасен: он не перезаписывает то, что уже лежит.

## Удаление

Установщик оставляет ровно известный набор файлов, поэтому удаление — точное, а не
«снести папку целиком». Запускается из той же папки alltoone: скрипт удаления лежит
в ней, поэтому сначала удаление, а папку репозитория удаляют уже после.

### Только пакет

```powershell
.\scripts\uninstall.ps1
```

```bash
./scripts/uninstall.sh
```

Убирает `alltoone` из Python и больше ничего не трогает.

### Пакет и workflow в проекте

```powershell
.\scripts\uninstall.ps1 -Target D:\work\my-project
```

```bash
./scripts/uninstall.sh --target ~/work/my-project
```

Убирает из проекта поставленные файлы (тот же список, что при установке) и затем сам
пакет. Если CLI нужен дальше — `-KeepPackage` / `--keep-package`: тогда пакет
останется, а проект очистится.

### Совсем чисто, вместе с историей передачи

```powershell
.\scripts\uninstall.ps1 -Target D:\work\my-project -Purge
```

```bash
./scripts/uninstall.sh --target ~/work/my-project --purge
```

`-Purge` / `--purge` дополнительно удаляет `.opencode/handoff/`, если он есть:
`STATE.md`, `files.txt` и собранные пакеты. Без него всё, что там было, остаётся —
это история работы, и молча её стирать нельзя.

### Что скрипт не удаляет

- **Изменённые файлы.** Если `AGENTS.md` или `opencode.jsonc` правились после
  установки, скрипт печатает `kept ... (changed since install)` и оставляет файл:
  удалить чужую правку молча — потеря данных. Удалить принудительно — `-Force` /
  `--force`.
- **Заработанные навыки** в `.opencode/skills/`: они написаны для проекта, а не
  поставлены; удаляется только опустевшая папка.
- **Файлы проекта** — код, документация, настройки: их скрипт не касается никогда.
- **Каталоги** `.opencode/plugins`, `.opencode/commands`, `.opencode` — только если
  опустели; чужое содержимое остаётся на месте.
- **Саму папку alltoone** — удали вручную, когда скрипт отработал.

После удаления в проекте не должно остаться `.opencode/plugins/context-budget`,
`.opencode/commands/handoff.md`, `.opencode/commands/resume.md` и `AGENTS.md` — если
вы их не правили. Навыки, состояние без `--purge` и ваши правки — останутся, так и
задумано.

| Параметр | Смысл |
| --- | --- |
| `-Target DIR` / `--target DIR` | какой проект чистить |
| `-Purge` / `--purge` | ещё и `.opencode/handoff/` |
| `-KeepPackage` / `--keep-package` | не удалять пакет alltoone |
| `-Force` / `--force` | удалить и изменённые файлы |
| `-Python PATH` / `--python PATH` | каким Python удалять пакет |

## Быстрый старт

```bash
# текущая папка → stdout
python -m alltoone

# другой проект → файл
python -m alltoone ../my-app -o context.md

# только исходники и документация
python -m alltoone --include "src/**" --include "*.md" -o context.md

# XML (удобно для Claude) с лимитом 100k токенов
python -m alltoone -f xml --max-tokens 100000 -o context.xml

# сразу в буфер обмена
python -m alltoone --clipboard

# только дерево файлов, без содержимого
python -m alltoone --tree-only

# развернуть контекст обратно в папку
python -m alltoone unpack context.md -o restored/
```

## Что попадает в файл

1. Шапка: имя проекта, дата, число файлов, оценка токенов.
2. Дерево проекта.
3. Каждый файл: заголовок с путём и код в блоке с подсветкой языка.

Форматы: `markdown` (по умолчанию), `xml`, `plain`.

## Фильтрация

По умолчанию исключаются:

- `.git`, `node_modules`, `.venv`, `__pycache__`, `dist`, `build`, `target`, `vendor` и прочий мусор;
- lock-файлы (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`), минифицированные бандлы и source maps;
- бинарные файлы (по расширению и по NUL-байтам);
- файлы больше 512 КБ (`--max-file-size`).

Дополнительно читаются `.gitignore` и `.alltooneignore` — включая вложенные в подпапки.
Правила работают как в Git: `!` возвращает файл, `dir/` — только каталоги, `**` — любая глубина.
`.alltooneignore` читается всегда, даже с `--no-gitignore` — это «свой» файл инструмента.

Свои правила:

```bash
python -m alltoone --exclude "*.test.ts" --exclude "docs/**"
python -m alltoone --exclude reference                 # выбросить каталог целиком
python -m alltoone --exclude-from my-rules.txt         # правила из файла
python -m alltoone --show-skipped                      # показать, что и почему выброшено
python -m alltoone --no-gitignore                      # не читать .gitignore
python -m alltoone --no-default-ignores                # отключить встроенный список
```

`--exclude` отсекает и файлы, и **каталоги целиком** (поддерево не обходится).
`--exclude-from` понимает полный синтаксис ignore-файлов, включая `!` и `dir/`.

### Справочные материалы в проекте

Если рядом с кодом лежит папка с документацией, выжимками или чужими исходниками,
её удобно исключить, не трогая остальное:

```bash
python -m alltoone . --exclude reference --exclude "docs/vendor/**" -o context.md
```

Ещё надёжнее — положить маркер прямо в папку, тогда правило поедет вместе с проектом
и сработает у любого, кто запустит alltoone:

```text
reference/.alltooneignore:
*
```

`*` игнорирует всё содержимое папки, включая сам маркер. Так же можно поступить с
`docs/`, `samples/`, `third_party/` — где угодно, где лежит не ваш код.

Проверить результат: `--show-skipped` печатает каждый пропущенный путь с причиной
(`ignored`, `excluded`, `binary`, `too large`, `not included`).

`--include` — белый список: если он задан, остаётся только то, что совпало.
Учти: `.gitignore` проверяется раньше, поэтому файл, исключённый им, не вернуть через
`--include` — используй `--no-gitignore`.

## Конфиг

Положи `alltoone.json` в корень проекта — CLI-флаги имеют приоритет:

```json
{
  "format": "markdown",
  "output": "context.md",
  "include": ["src/**", "*.md"],
  "exclude": ["*.test.ts"],
  "use_gitignore": true,
  "use_default_ignores": true,
  "max_file_size_kb": 512,
  "max_tokens": 120000,
  "tree": true,
  "files": true,
  "clipboard": false
}
```

Другой файл: `--config path/to/config.json`.

## Все опции

| Опция | Описание |
| --- | --- |
| `path` | папка или отдельный файл (по умолчанию `.`) |
| `-o, --output FILE` | куда писать (`-` = stdout) |
| `-f, --format` | `markdown`, `xml`, `plain` |
| `--include GLOB` | только совпавшие файлы (можно несколько) |
| `--exclude GLOB` | исключить файлы или каталоги целиком |
| `--exclude-from FILE` | правила исключения из файла (gitignore-синтаксис) |
| `--show-skipped` | показать все пропущенные пути и причины |
| `--no-gitignore` | не читать `.gitignore` (`.alltooneignore` читается всегда) |
| `--no-default-ignores` | без встроенного списка |
| `--max-file-size KB` | лимит размера файла, КБ |
| `--max-tokens N` | разбить результат на части по N токенов |
| `--tree-only` | только дерево |
| `--no-tree` | без дерева |
| `--no-integrity` | без SHA-256 манифеста (экономит токены) |
| `--clipboard` | скопировать результат |
| `--config FILE` | путь к конфигу |
| `-q, --quiet` | без сводки в stderr |

## Разбиение на части

Если проект не влезает в контекст:

```bash
python -m alltoone -o context.md --max-tokens 60000
# → context.part1.md, context.part2.md, ...
```

Режется по границам файлов, каждый файл целиком попадает в одну часть.
Каждая часть самодостаточна: шапка и дерево повторяются.

## Перенос работы в новый чат

`alltoone handoff` собирает **один файл**: состояние сессии, полное дерево проекта
и только те файлы, которые нужны, чтобы продолжить.

```bash
python -m alltoone handoff
# → .opencode/handoff/pack.md
```

```text
.opencode/handoff/
├── STATE.md    # цель, сделано, дальше, решения, файлы
├── files.txt   # что попадёт в пакет, по одному пути на строку
└── pack.md     # готовый файл для нового чата
```

Дерево в пакете всегда полное — новый чат видит карту проекта и может попросить
недостающие файлы по имени. `STATE.md` и `files.txt` пишет агент; шаблон состояния
лежит в `AGENTS.md`.

| Опция | Описание |
| --- | --- |
| `--state FILE` | файл состояния (по умолчанию `.opencode/handoff/STATE.md`) |
| `--files-from FILE` | список путей (по умолчанию `.opencode/handoff/files.txt`) |
| `-o, --output FILE` | куда писать пакет |
| `-f, --format` | `markdown`, `xml`, `plain` |
| `--max-file-size KB` | лимит размера файла |
| `--no-tree` | без дерева |
| `--no-integrity` | без SHA-256 манифеста |
| `--check` | проверить `STATE.md`, `files.txt` и каталог навыков, ничего не писать |

Проверить, что пакет не оставит новый чат без контекста, можно без сборки:

```bash
python -m alltoone handoff --check
# 0 — всё в порядке, 1 — список проблем в stderr
```

Проверяется: заголовок `# State`, все секции схемы из `AGENTS.md`, лимит 60 строк,
существование перечисленных путей, дубликаты, абсолютные пути и `..`, файлы,
которые alltoone всё равно пропустит (`.gitignore`, бинарники), и формат навыков
в `.opencode/skills/`, если каталог есть. Обычная сборка при нарушении схемы
печатает предупреждение, но пакет всё равно пишет.

В OpenCode цикл автоматизирован: плагин `.opencode/plugins/context-budget`
добавляет в каждый запрос строку `[budget]`, а команды `/handoff` и `/resume`
готовят пакет и поднимают работу в новом чате.

На `critical` плагин умеет сам запросить сжатие (`ctx.session.compact`), но по
умолчанию **не** делает этого: сжатие переписывает историю с потерями, а новый
чат с `/resume` ничего не теряет. Включить — только для проектов, где новый чат
не вариант:

```jsonc
"plugins": [
  {
    "package": "./.opencode/plugins/context-budget",
    "options": { "autoCompact": true },
  },
]
```

Запись в `plugins` и автозагрузка из `.opencode/plugins/` дают один экземпляр
плагина, поэтому опции можно передавать, не боясь двойного счётчика.

Тот же плагин сам находит пакет в новом чате: `"autoResume": true` добавляет в
первый запрос сессии одну строку-указатель на `.opencode/handoff/pack.md`. В
поставляемом `opencode.jsonc` опция включена — новый чат в этом проекте обычно
продолжает работу; там, где это не так, поставь `false`. Указатель не читает
пакет: решает модель, а пакет стоит ~30k токенов. Указатель называет размер файла
и просит дочитать пакет частями: ~130 КБ в одно чтение не влезает. Уже существующий
`opencode.jsonc` установщик не перезаписывает, поэтому в настроенном проекте
опцию включают руками. Без плагина близкий эффект даёт
`"instructions": [".opencode/handoff/STATE.md"]`: состояние читается в каждом
запросе, но без дерева и файлов пакета.

## Навыки

Навык — это рецепт, записанный после того, как одно и то же не получалось несколько
раз, а потом получилось. Он лежит в `.opencode/skills/<slug>/SKILL.md` и
подгружается по описанию: тело стоит токенов только когда понадобится, а в контексте
постоянно висит одна строка каталога (~20–25 токенов).

```text
.opencode/skills/
├── skill-template.md              # форма; её копирует установщик
└── powershell-native-stderr/      # пример: заработан, а не выдуман
    └── SKILL.md
```

Что проверяет `handoff --check`:

- `name` в шапке совпадает с именем папки, папка — строчный slug;
- `description` начинается с симптома (`fails`, `ошибка`, `падает`…): искать будут
  по тексту ошибки, а не по теме;
- тело не длиннее 50 строк и содержит строку `Proof:` — id сессии и наблюдённый
  результат;
- описания не дублируются, в каталоге не больше 12 навыков.

Записывать надо в момент решения, пока команда дословна, и только если сообщение об
ошибке ответа не содержало. То, что и так написано в ошибке, разовый сбой окружения
и случайно сработавшее — не навык: им место в `STATE.md`. Один файл на класс
симптома; когда случай повторяется, навык правят, а не плодят второй.

Автоматики нет: это осознанное решение. Провалы `shell` не пишутся в базу OpenCode как
ошибки инструмента, поэтому триггер («третья попытка — открой каталог») остаётся в
сессии, а `scripts/usage.py` только показывает повторяющиеся ошибки как кандидатов.

## Развернуть обратно

Контекст — это полноценный архив проекта. Обратная команда раскладывает его по папкам:

```bash
python -m alltoone unpack context.md              # → ./context/
python -m alltoone unpack context.md -o app/      # → ./app/
python -m alltoone unpack ctx.xml -o app/         # формат определится сам
python -m alltoone unpack context.md -o app/ --dry-run   # только показать
```

Что важно:

- **Побайтовая точность** для `markdown` и `xml`: pack → unpack возвращает ровно то же
  содержимое, включая пустые файлы, файлы без перевода строки на конце и тройные бэктики
  внутри кода.
- **Безопасность**: абсолютные пути, `..` и всё, что выходит за пределы целевой папки,
  отклоняется с ошибкой.
- **Не перезаписывает** существующие файлы без `--force`.
- Формат определяется по содержимому (расширение `.xml`, заголовок `# Project context:`).
  Если файл нестандартный — укажи `--format markdown|xml|plain`.
- Пакет `alltoone handoff` разворачивается тем же `unpack` без `--format`: состояние в шапке
  не мешает, в том числе если оно цитирует markdown с заголовками и фенсами. Само состояние
  файлом не восстанавливается — оно остаётся текстом в шапке пакета.

| Опция | Описание |
| --- | --- |
| `context` | файл контекста |
| `-o, --output DIR` | куда разворачивать (по умолчанию `./<имя файла>`) |
| `-f, --format` | принудительно задать формат |
| `--force` | перезаписывать существующие файлы |
| `--dry-run` | показать список, ничего не писать |
| `--no-verify` | не проверять контрольные суммы |
| `-q, --quiet` | без сводки |

## Проверка целостности

Контекст легко испортить: обрезать при копировании, потерять строку при вставке в чат.
Поэтому в шапку пишется манифест:

````text
## Integrity

```text
sha256 manifest v1
e790e3ad...4427b  .gitignore
9c8619c4...db27e  README.md
total 4f1c...9ab2
```
````

- `sha256` каждого файла считается от его содержимого **в том виде, как оно лежит в контексте**.
- `total` — хеш самого манифеста, поэтому потерянная строка тоже видна.

`unpack` проверяет всё **до записи**: при расхождении не создаётся вообще ничего, чтобы не
получить полуразвёрнутый проект. В сводке видно `checks 13 files verified (sha256)`.

```bash
python -m alltoone unpack context.md -o app/   # упадёт с checksum mismatch
python -m alltoone unpack context.md -o app/ --no-verify   # распаковать как есть
```

Манифест можно отключить при упаковке: `--no-integrity` (экономит ~17 токенов на файл).
Это защита от случайной порчи, а не от подделки: тот, кто правит контекст, может
пересчитать хеши.

## Оценка токенов

Точного токенизатора внутри нет (это была бы зависимость на десятки мегабайт).
Используется эвристика: латиница ≈ 4 символа на токен, кириллица и CJK ≈ 1.8.
Погрешность обычно в пределах 10–20%, для решения «влезет / не влезет» этого достаточно.

## Статистика использования

`python scripts/usage.py` — read-only отчёт по базе OpenCode (`opencode.db`): кэш
по сессиям и моделям, сколько раз новая сессия перечитывала пакет, какие файлы из
`files.txt` реально открывались, какие ошибки инструментов повторяются (кандидаты
в навыки) и какой каталог навыков сейчас в проекте. База открывается только на
чтение; в выводе — пути, счётчики и имена моделей, без содержимого промптов.
В пакет не входит, зависимостей нет.

```bash
python scripts/usage.py --sessions 20
```

## Ограничения

- Только текстовые файлы; бинарники пропускаются.
- Символические ссылки на каталоги не обходятся (защита от циклов).
- Кодировки: UTF-8, UTF-16, cp1251, cp1252, latin-1. Остальные читаются как latin-1.
- `.gitignore` поддерживается в разумном подмножестве спецификации, а не побайтово.
- При упаковке переводы строк нормализуются к `LF`, поэтому файлы с `CRLF` восстановятся
  с `LF`. Пустые каталоги не сохраняются — в контексте есть только файлы.
- Метр контекста и автоуказатель на пакет есть только в OpenCode (плагин, API V2).
  Упаковка, распаковка, `handoff --check` и схема состояния переносимы.
