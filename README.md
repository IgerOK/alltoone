# alltoone

Продолжение работы с ИИ без потери нити: сессия упирается в лимит контекста —
`/handoff` собирает состояние, карту проекта и нужные файлы в один файл, а новый
чат поднимает работу через `/resume`. Без зависимостей, один `python`.

Три части:

- **`alltoone` (CLI)** — упаковка проекта в один файл и обратно (`pack`, `unpack`).
  Это же основа пакета для переноса: один файл, который читает агент.
- **Workflow переноса** — `STATE.md` (брифинг до 60 строк), `files.txt` (что нужно
  дальше), `pack.md`; команды `/handoff` и `/resume` в OpenCode, `handoff --check`.
- **Плагин `context-budget`** — строка `[budget]` в каждом запросе из реальных
  токенов провайдера и режимы 70/85/92%, по которым агент готовит перенос.

Упаковка остаётся самостоятельным сценарием: отдать проект другому агенту на
анализ, вложить в письмо, оценить объём перед работой.

```
проект/                      alltoone-context.md
├── src/            ──►      ├── дерево проекта
│   ├── main.py              ├── ### `src/main.py` + код
│   └── utils.py             └── ### `src/utils.py` + код
├── README.md
└── .gitignore
```

## Зачем именно в OpenCode

Обычный чат принимает файлы, но не помнит, где остановился. В OpenCode этот набор
закрывает ровно это:

- **Метр из реальных токенов.** Строка `[budget] 158k/200k used (79%)` приходит в
  каждом запросе; цифры берутся из отчёта провайдера, а не из оценки модели.
- **Порог напоминает сам.** 70% — агент обновляет `STATE.md`, 85% — собирает пакет
  и говорит открыть новый чат, 92% — просит остановиться.
- **Перенос одним файлом.** `/handoff` и `/resume` передают не историю, а брифинг:
  цель, сделано, дальше, решения, нужные файлы и полная карта проекта.
- **Кэш не страдает.** Строка уходит в хвост сообщений: 89–96% промпта читается из
  кэша (при инъекции в системный промпт было 2%).
- **Выход всегда на виду.** Каждый запрос заканчивается на `new chat: /resume` —
  даже в `normal`, задолго до порога.
- **Всё локально.** Состояние, список файлов и журнал — в `.opencode/handoff/`.

Цена: одна служебная строка на запрос и ~30k токенов на `/resume`.

## Зачем

- **Продолжить в новом чате без пересказа** — состояние, решения и нужные файлы
  уже лежат в пакете; `/resume` их читает.
- **Отдать проект другому агенту одним файлом** — анализ, ревью, вложение в письмо.
- **Уложиться в лимит токенов** — `--max-tokens` режет по границам файлов.
- **Вернуть файлы обратно** — `unpack` проверяет SHA-256 до записи.

## Установка

Ничего ставить не нужно, достаточно Python 3.10+:

```bash
python -m alltoone .            # из папки проекта
```

Либо как команду:

```bash
pip install -e .
alltoone .
```

С GitHub — одной командой, после `git clone`:

```bash
git clone https://github.com/<ваш-логин>/alltoone
cd alltoone

# Windows
.\scripts\install.ps1
# Linux / macOS
./scripts/install.sh
```

Скрипт проверяет версию Python, ставит пакет в режиме editable (дальше хватает
`git pull`, переустанавливать не нужно) и печатает следующий шаг.

### Развернуть handoff-цикл в своём проекте

Тем же скриптом, с указанием папки проекта:

```bash
.\scripts\install.ps1 -Target D:\work\my-project
./scripts/install.sh --target ~/work/my-project
```

Копируются `.opencode/plugins/context-budget`, `.opencode/commands/{handoff,resume}.md`,
`AGENTS.md` и `opencode.jsonc`. Состояние (`.opencode/handoff/`) не копируется никогда —
оно принадлежит конкретному проекту. Существующие файлы не перезаписываются без
`-Force` / `--force`.


## Быстрый старт

```bash
# текущая папка → stdout
python -m alltoone

# другой проект → файл
python -m alltoone ../my-app -o context.md

# только исходники и документация
python -m alltoone --include "src/**" --include "*.md" -o context.md

# XML (удобно для Claude) с лимитом 100k токенов
python -m alltoone -f xml --max-tokens 100000 -o context.xml

# сразу в буфер обмена
python -m alltoone --clipboard

# только дерево файлов, без содержимого
python -m alltoone --tree-only

# развернуть контекст обратно в папку
python -m alltoone unpack context.md -o restored/
```

## Что попадает в файл

1. Шапка: имя проекта, дата, число файлов, оценка токенов.
2. Дерево проекта.
3. Каждый файл: заголовок с путём и код в блоке с подсветкой языка.

Форматы: `markdown` (по умолчанию), `xml`, `plain`.

## Фильтрация

По умолчанию исключаются:

- `.git`, `node_modules`, `.venv`, `__pycache__`, `dist`, `build`, `target`, `vendor` и прочий мусор;
- lock-файлы (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`), минифицированные бандлы и source maps;
- бинарные файлы (по расширению и по NUL-байтам);
- файлы больше 512 КБ (`--max-file-size`).

Дополнительно читаются `.gitignore` и `.alltooneignore` — включая вложенные в подпапки.
Правила работают как в Git: `!` возвращает файл, `dir/` — только каталоги, `**` — любая глубина.
`.alltooneignore` читается всегда, даже с `--no-gitignore` — это «свой» файл инструмента.

Свои правила:

```bash
python -m alltoone --exclude "*.test.ts" --exclude "docs/**"
python -m alltoone --exclude reference                 # выбросить каталог целиком
python -m alltoone --exclude-from my-rules.txt         # правила из файла
python -m alltoone --show-skipped                      # показать, что и почему выброшено
python -m alltoone --no-gitignore                      # не читать .gitignore
python -m alltoone --no-default-ignores                # отключить встроенный список
```

`--exclude` отсекает и файлы, и **каталоги целиком** (поддерево не обходится).
`--exclude-from` понимает полный синтаксис ignore-файлов, включая `!` и `dir/`.

### Справочные материалы в проекте

Если рядом с кодом лежит папка с документацией, выжимками или чужими исходниками,
её удобно исключить, не трогая остальное:

```bash
python -m alltoone . --exclude reference --exclude "docs/vendor/**" -o context.md
```

Ещё надёжнее — положить маркер прямо в папку, тогда правило поедет вместе с проектом
и сработает у любого, кто запустит alltoone:

```text
reference/.alltooneignore:
*
```

`*` игнорирует всё содержимое папки, включая сам маркер. Так же можно поступить с
`docs/`, `samples/`, `third_party/` — где угодно, где лежит не ваш код.

Проверить результат: `--show-skipped` печатает каждый пропущенный путь с причиной
(`ignored`, `excluded`, `binary`, `too large`, `not included`).

`--include` — белый список: если он задан, остаётся только то, что совпало.
Учти: `.gitignore` проверяется раньше, поэтому файл, исключённый им, не вернуть через
`--include` — используй `--no-gitignore`.

## Конфиг

Положи `alltoone.json` в корень проекта — CLI-флаги имеют приоритет:

```json
{
  "format": "markdown",
  "output": "context.md",
  "include": ["src/**", "*.md"],
  "exclude": ["*.test.ts"],
  "use_gitignore": true,
  "use_default_ignores": true,
  "max_file_size_kb": 512,
  "max_tokens": 120000,
  "tree": true,
  "files": true,
  "clipboard": false
}
```

Другой файл: `--config path/to/config.json`.

## Все опции

| Опция | Описание |
| --- | --- |
| `path` | папка или отдельный файл (по умолчанию `.`) |
| `-o, --output FILE` | куда писать (`-` = stdout) |
| `-f, --format` | `markdown`, `xml`, `plain` |
| `--include GLOB` | только совпавшие файлы (можно несколько) |
| `--exclude GLOB` | исключить файлы или каталоги целиком |
| `--exclude-from FILE` | правила исключения из файла (gitignore-синтаксис) |
| `--show-skipped` | показать все пропущенные пути и причины |
| `--no-gitignore` | не читать `.gitignore` (`.alltooneignore` читается всегда) |
| `--no-default-ignores` | без встроенного списка |
| `--max-file-size KB` | лимит размера файла, КБ |
| `--max-tokens N` | разбить результат на части по N токенов |
| `--tree-only` | только дерево |
| `--no-tree` | без дерева |
| `--no-integrity` | без SHA-256 манифеста (экономит токены) |
| `--clipboard` | скопировать результат |
| `--config FILE` | путь к конфигу |
| `-q, --quiet` | без сводки в stderr |

## Разбиение на части

Если проект не влезает в контекст:

```bash
python -m alltoone -o context.md --max-tokens 60000
# → context.part1.md, context.part2.md, ...
```

Режется по границам файлов, каждый файл целиком попадает в одну часть.
Каждая часть самодостаточна: шапка и дерево повторяются.

## Перенос работы в новый чат

`alltoone handoff` собирает **один файл**: состояние сессии, полное дерево проекта
и только те файлы, которые нужны, чтобы продолжить.

```bash
python -m alltoone handoff
# → .opencode/handoff/pack.md
```

```text
.opencode/handoff/
├── STATE.md    # цель, сделано, дальше, решения, файлы
├── files.txt   # что попадёт в пакет, по одному пути на строку
└── pack.md     # готовый файл для нового чата
```

Дерево в пакете всегда полное — новый чат видит карту проекта и может попросить
недостающие файлы по имени. `STATE.md` и `files.txt` пишет агент; шаблон состояния
лежит в `AGENTS.md`.

| Опция | Описание |
| --- | --- |
| `--state FILE` | файл состояния (по умолчанию `.opencode/handoff/STATE.md`) |
| `--files-from FILE` | список путей (по умолчанию `.opencode/handoff/files.txt`) |
| `-o, --output FILE` | куда писать пакет |
| `-f, --format` | `markdown`, `xml`, `plain` |
| `--max-file-size KB` | лимит размера файла |
| `--no-tree` | без дерева |
| `--no-integrity` | без SHA-256 манифеста |
| `--check` | проверить `STATE.md` и `files.txt`, ничего не писать |

Проверить, что пакет не оставит новый чат без контекста, можно без сборки:

```bash
python -m alltoone handoff --check
# 0 — всё в порядке, 1 — список проблем в stderr
```

Проверяется: заголовок `# State`, все секции схемы из `AGENTS.md`, лимит 60 строк,
существование перечисленных путей, дубликаты, абсолютные пути и `..`, а также файлы,
которые alltoone всё равно пропустит (`.gitignore`, бинарники). Обычная сборка при
нарушении схемы печатает предупреждение, но пакет всё равно пишет.

В OpenCode цикл автоматизирован: плагин `.opencode/plugins/context-budget`
добавляет в каждый запрос строку `[budget]`, а команды `/handoff` и `/resume`
готовят пакет и поднимают работу в новом чате.

На `critical` плагин умеет сам запросить сжатие (`ctx.session.compact`), но по
умолчанию **не** делает этого: сжатие переписывает историю с потерями, а новый
чат с `/resume` ничего не теряет. Включить — только для проектов, где новый чат
не вариант:

```jsonc
"plugins": [
  {
    "package": "./.opencode/plugins/context-budget",
    "options": { "autoCompact": true },
  },
]
```

Запись в `plugins` и автозагрузка из `.opencode/plugins/` дают один экземпляр
плагина, поэтому опции можно передавать, не боясь двойного счётчика.

Тот же плагин сам находит пакет в новом чате: `"autoResume": true` добавляет в
первый запрос сессии одну строку-указатель на `.opencode/handoff/pack.md`. В
поставляемом `opencode.jsonc` опция включена — новый чат в этом проекте обычно
продолжает работу; там, где это не так, поставь `false`. Указатель не читает
пакет: решает модель, а пакет стоит ~30k токенов. Указатель называет размер файла
и просит дочитать пакет частями: ~130 КБ в одно чтение не влезает. Уже существующий
`opencode.jsonc` установщик не перезаписывает, поэтому в настроенном проекте
опцию включают руками. Без плагина близкий эффект даёт
`"instructions": [".opencode/handoff/STATE.md"]`: состояние читается в каждом
запросе, но без дерева и файлов пакета.

## Развернуть обратно

Контекст — это полноценный архив проекта. Обратная команда раскладывает его по папкам:

```bash
python -m alltoone unpack context.md              # → ./context/
python -m alltoone unpack context.md -o app/      # → ./app/
python -m alltoone unpack ctx.xml -o app/         # формат определится сам
python -m alltoone unpack context.md -o app/ --dry-run   # только показать
```

Что важно:

- **Побайтовая точность** для `markdown` и `xml`: pack → unpack возвращает ровно то же
  содержимое, включая пустые файлы, файлы без перевода строки на конце и тройные бэктики
  внутри кода.
- **Безопасность**: абсолютные пути, `..` и всё, что выходит за пределы целевой папки,
  отклоняется с ошибкой.
- **Не перезаписывает** существующие файлы без `--force`.
- Формат определяется по содержимому (расширение `.xml`, заголовок `# Project context:`).
  Если файл нестандартный — укажи `--format markdown|xml|plain`.
- Пакет `alltoone handoff` разворачивается тем же `unpack` без `--format`: состояние в шапке
  не мешает, в том числе если оно цитирует markdown с заголовками и фенсами. Само состояние
  файлом не восстанавливается — оно остаётся текстом в шапке пакета.

| Опция | Описание |
| --- | --- |
| `context` | файл контекста |
| `-o, --output DIR` | куда разворачивать (по умолчанию `./<имя файла>`) |
| `-f, --format` | принудительно задать формат |
| `--force` | перезаписывать существующие файлы |
| `--dry-run` | показать список, ничего не писать |
| `--no-verify` | не проверять контрольные суммы |
| `-q, --quiet` | без сводки |

## Проверка целостности

Контекст легко испортить: обрезать при копировании, потерять строку при вставке в чат.
Поэтому в шапку пишется манифест:

````text
## Integrity

```text
sha256 manifest v1
e790e3ad...4427b  .gitignore
9c8619c4...db27e  README.md
total 4f1c...9ab2
```
````

- `sha256` каждого файла считается от его содержимого **в том виде, как оно лежит в контексте**.
- `total` — хеш самого манифеста, поэтому потерянная строка тоже видна.

`unpack` проверяет всё **до записи**: при расхождении не создаётся вообще ничего, чтобы не
получить полуразвёрнутый проект. В сводке видно `checks 13 files verified (sha256)`.

```bash
python -m alltoone unpack context.md -o app/   # упадёт с checksum mismatch
python -m alltoone unpack context.md -o app/ --no-verify   # распаковать как есть
```

Манифест можно отключить при упаковке: `--no-integrity` (экономит ~17 токенов на файл).
Это защита от случайной порчи, а не от подделки: тот, кто правит контекст, может
пересчитать хеши.

## Оценка токенов

Точного токенизатора внутри нет (это была бы зависимость на десятки мегабайт).
Используется эвристика: латиница ≈ 4 символа на токен, кириллица и CJK ≈ 1.8.
Погрешность обычно в пределах 10–20%, для решения «влезет / не влезет» этого достаточно.

## Статистика использования

`python scripts/usage.py` — read-only отчёт по базе OpenCode (`opencode.db`): кэш
по сессиям и моделям, сколько раз новая сессия перечитывала пакет, какие файлы из
`files.txt` реально открывались. База открывается только на чтение; в выводе —
пути, счётчики и имена моделей, без содержимого промптов. В пакет не входит,
зависимостей нет.

```bash
python scripts/usage.py --sessions 20
```

## Ограничения

- Только текстовые файлы; бинарники пропускаются.
- Символические ссылки на каталоги не обходятся (защита от циклов).
- Кодировки: UTF-8, UTF-16, cp1251, cp1252, latin-1. Остальные читаются как latin-1.
- `.gitignore` поддерживается в разумном подмножестве спецификации, а не побайтово.
- При упаковке переводы строк нормализуются к `LF`, поэтому файлы с `CRLF` восстановятся
  с `LF`. Пустые каталоги не сохраняются — в контексте есть только файлы.
